# UI Heuristics

Use these heuristics when a design decision is ambiguous.

## Hierarchy

Ask:

- What is the user's primary task?
- What must be noticed within a few seconds?
- What can safely become secondary or collapsed?

Use layout and spacing before decoration to communicate importance.

## Composition

Prefer a composition that explains the task naturally.

Avoid defaulting to:

- hero + three cards + CTA
- sidebar + header + KPI cards
- every section wrapped in a card

These are patterns, not requirements.

## Color

Use color to communicate roles:

- primary action
- neutral structure
- success
- warning
- error
- information

Do not add accent colors only to make an interface look more "designed".

## Surfaces

Prefer one clear surface system. Use border, contrast and restrained elevation intentionally.

## Typography

Use a small type scale with clear relationships between title, section heading, body, helper text and metadata.

Do not create hierarchy by making everything bold.

## Density

Choose density based on the task:

- reading/review → more breathing room
- operations/data entry → compact but scannable
- tables/lists → alignment and consistency first

## Motion

Add motion only when it explains state, confirms action or improves continuity.

Do not animate for decoration alone.
