# Frontend Design Validation Checklist

## Product fit

- [ ] Primary task is obvious.
- [ ] Screen uses existing DemoXV patterns where appropriate.
- [ ] No second visual language was introduced.

## Visual quality

- [ ] Typography hierarchy is clear.
- [ ] Spacing is consistent.
- [ ] Colors have meaningful roles.
- [ ] Surfaces and shadows are restrained.
- [ ] Design is not dependent on decorative gradients or excessive rounding.

## Interaction

- [ ] Hover/focus/active states are present where relevant.
- [ ] Loading/empty/error/success states are handled where relevant.
- [ ] Buttons communicate actions clearly.

## Responsive

- [ ] Desktop layout works.
- [ ] Tablet behavior is intentional.
- [ ] Mobile layout is intentionally composed.
- [ ] Tables, forms and navigation remain usable on small screens.

## Accessibility

- [ ] Semantic elements are used where appropriate.
- [ ] Labels and accessible names are present.
- [ ] Focus is visible.
- [ ] Status is not communicated by color alone.

## Engineering

- [ ] Existing components were reused where appropriate.
- [ ] No unnecessary dependency was added.
- [ ] TypeScript remains strictly typed.
- [ ] Relevant validation was run and results are known.
